QBX Premium Safes

Production-ready placeable safe system for QBox using ox_inventory, ox_lib, ox_target, oxmysql, and a modern NUI dashboard.

A complete safe management solution with granular permissions, break-in mechanics, upgradeable storage, persistence system, audio-visual alarms, police dispatch integration, and full transaction logging.

Key Highlights

  • Place safes with custom names and prop models
  • Granular permission system (deposit, withdraw, manage)
  • 5 purchasable upgrades (storage tiers, alarm, tracking, access control, owner online)
  • 8 storage tiers with progressive unlocking ($25K-$100K each)
  • Dynamic item weight - safe gets heavier with each upgrade
  • Audio-visual alarm system with map blips
  • Police dispatch integration (origin_dispatch supported)
  • Code breaker break-in mechanics with cooldowns and lockouts
  • Safe persistence - pick up and place back with everything intact
  • Full audit trail with Discord webhooks
  • Modern NUI dashboard with tab permission gating

Installation Guide

Requirements

  • qbx_core - QBox framework core
  • ox_inventory - Item and inventory management
  • ox_lib - Utility library and UI components
  • ox_target - Third-eye interaction system
  • oxmysql - Database operations
Important: Ensure all dependencies are running BEFORE starting qbx_premium_safes. Check your server.cfg load order.
1

Download & Install

  1. Download the resource and place it in your resources folder
  2. Add ensure qbx_premium_safes to your server.cfg (after dependencies)
2

Database Setup (Automatic)

The schema is automatically created on first startup. No manual SQL import is needed. The system auto-creates these tables:

  • safes - Safe records with upgrades, placement state, and ownership
  • safe_access - Member permission entries
  • safe_logs - Transaction history with actor tracking
  • safe_contributions - Member contribution tracking
  • safe_tracked_items - Per-safe tracking item configuration
  • safe_tracker_progress - Member progress tracking
  • safe_tracker_archive - Period archival data
  • safe_crack_attempts - Break-in attempt logs
Automatic Versioning: Future updates are applied automatically. The system tracks schema version and runs migrations as needed.
3

Add Items to ox_inventory

Add the following items to ox_inventory/data/items.lua:

items.lua
['placablesafe'] = {
    label = 'Placeable Safe',
    weight = 15000,
    stack = false,
    close = true,
    description = 'A heavy secure safe. Place it to store your valuables.',
    server = {
        export = 'qbx_premium_safes.placablesafe'
    }
},

['codecracker'] = {
    label = 'Code Cracker',
    weight = 2000,
    stack = true,
    close = true,
    description = 'Electronic device used to attempt forced entry on secure safes.'
},
Note: The weight = 15000 (15kg) is the base weight. This will dynamically increase as upgrades are purchased. See the Dynamic Weight System section.
4

Copy Item Icons

Copy the item icons from item_Icons/ folder to your ox_inventory images folder:

  • Copy placablesafe.png and codecracker.png
  • Paste into ox_inventory/web/images/
5

Configure Dispatch (Optional)

If you want police alerts on break-ins, configure the dispatch hook in config.lua:

config.lua - Police Dispatch Hook
Config.Hooks = {
    policeAlert = function(payload)
        exports['origin_dispatch']:SendDispatch({
            job = 'police',
            calls = 'Safe Break-In',
            coords = payload.coords,
            information = ('Break-in attempt at safe: %s'):format(payload.safeName or ('#' .. tostring(payload.safeId))),
        })
    end,
    -- other hooks...
}

For other dispatch systems, modify the export call accordingly. The payload contains:

  • coords - Safe location (vector3)
  • safeName - Name of the safe
  • safeId - Database ID
  • playerName - Name of the burglar (if available)
6

Add Alarm Sound (Optional)

The alarm system supports custom audio. Add your sound file:

  1. Place a .ogg file in web/sounds/ folder
  2. Update Config.AlarmUpgrade.soundFile with the filename (without .ogg extension)
config.lua
Config.AlarmUpgrade = {
    -- ...
    soundFile = 'sound1', -- File: web/sounds/sound1.ogg
    -- ...
}

Configure Webhooks (Optional)

Add Discord webhook URLs for event logging:

config.lua
Config.Logging = {

    webhooks = {

    }
}
Installation Complete! Restart your server or use refresh then ensure qbx_premium_safes in the console.

Features

Placement & Ownership

Place safes with unique names and automatic ownership tracking. Custom prop support with display names.

Permission System

Granular per-member access control: deposit, withdraw, and manage permissions. Add offline players by citizen ID.

Manager Role

Players with "manage" permission can edit members and purchase upgrades - not just the owner.

Storage Tiers

8 upgradeable tiers with increasing capacity. Progressively unlock more slots (40→120) and weight (250kg→3000kg).

Access Control Upgrade

Purchasable upgrade to restrict stash access. Without it, anyone can access the safe. Hides Access tab until purchased.

Audio-Visual Alarm

Flashing UI alert with safe name, custom .ogg sound, and map blip at break-in location.

Police Dispatch

Automatic police alerts on break-in attempts. Supports origin_dispatch out of the box.

Owner Online Requirement

Purchasable upgrade that prevents break-ins when the safe owner is offline.

Member Tracking

Monitor contributions and member activity. Purchasable tracking upgrade unlocks Tracking tab.

Safe Persistence

Pick up safes with all items and upgrades intact. Place back down and everything is restored. Ownership transfers to placer.

Dynamic Weight

Safe item weight increases with each upgrade purchased. Configurable base weight and max cap.

Break-In System

Crack safes using code crackers. Configurable success chance, cooldowns, lockout timers.

Direct Stash Access

Use ox_target to open stash directly. Respects deposit/withdraw permissions. Withdrawal blocked for deposit-only users.

Unknown Actor Masking

Break-ins via code cracker log transactions as "Unknown" to maintain anonymity.

Full Logging

Complete audit trail of all transactions with Discord webhook support.

UI Sound Toggle

Players can toggle alarm sounds on/off via settings. Preference persists in localStorage.

Purchasable Upgrades

All upgrades are purchased through the NUI dashboard and persist with the safe. Players with "manage" permission can purchase upgrades.

Upgrade Price Description
Storage Tiers $25K - $100K 8 tiers increasing slots (40→120) and weight (250kg→3000kg). Must be purchased in order. Tiers 1-3: $25K each. Tiers 4-8: $100K each.
Access Control $25,000 Restricts stash access to allowed users only. Without this upgrade, anyone can access the stash. Access tab hidden until purchased.
Silent Alarm $35,000 Triggers audio-visual alert on break-in. Shows safe name in notification. Creates map blip at safe location. Alerts police via dispatch.
Owner Online $40,000 Prevents break-ins when the safe owner is offline. Burglars will be notified the owner is unavailable.
Member Tracking $30,000 Enables member contribution tracking and progress goals. Unlocks Tracking tab in UI.
Tip: The Access tab is only visible when the Access Control upgrade is owned. The Tracking tab is only visible when the Tracking upgrade is owned. Settings tab is only visible to players with "manage" permission.

Permissions Breakdown

Role Deposit Withdraw Manage Capabilities
Owner ✓ ✓ ✓ Full control, edit members, purchase upgrades, pickup safe, transfer ownership on placement
Manager ✓ ✓ ✓ Edit member permissions, purchase upgrades, view Access/Settings tabs
Withdraw ✓ ✓ - Can deposit and withdraw items
Deposit Only ✓ - - Can only add items to safe. Withdrawal is blocked via inventory hooks.

Access Control Behavior

  • With Access Control Upgrade: Only users with explicit permissions can access the stash
  • Without Access Control Upgrade: Anyone can access and interact with the stash
  • Withdrawal Blocking: Deposit-only users cannot withdraw items even with direct stash access

Permission Actions

  • Withdraw Permission: Allows taking items from the safe
  • Deposit Permission: Allows adding items to the safe
  • Manage Permission: Allows editing member permissions, purchasing upgrades, and viewing Access/Settings tabs

Adding Offline Players

You can add players to safe access even if they're offline by entering their Citizen ID manually in the access management UI.

Safe Persistence System

Safes maintain their complete state when picked up and placed back down, including all items and upgrades.

How It Works

  • Pickup: When an owner picks up a safe, the database record is marked as is_placed = 0 but NOT deleted
  • Item Metadata: The safe item stores the Safe ID and safe name in its metadata
  • Dynamic Weight: The item weight is recalculated based on purchased upgrades
  • Placement: When placed back down, the system detects the Safe ID and relinks to the existing database record
  • Ownership Transfer: The player who places the safe becomes the new owner (coordinates, name, and owner all update)

What Persists

All Items

Every item in the stash remains intact through pickup/placement.

Storage Tier

Purchased storage upgrades are preserved.

All Upgrades

Alarm, Tracking, Access Control, Owner Online - all preserved.

Access List

All member permissions remain configured.

Important: Only the owner can pick up a safe. When placed by a different player, ownership transfers to that player automatically.

Alarm System

The Silent Alarm upgrade provides comprehensive break-in detection with multiple notification channels.

Notification Channels

Channel Trigger Details
Owner Alert Break-in attempt starts NUI popup with safe name, flashing animation, and audio
Map Blip Break-in attempt starts Red flashing blip at safe location. Duration configurable (default: 30 seconds)
Police Dispatch Break-in attempt starts Alert sent to police via configured dispatch system

Alarm Configuration

config.lua
Config.AlarmUpgrade = {
    enabled = true,
    label = 'Silent Alarm',
    currency = 'cash',
    price = 35000,
    notifyOwner = true,
    notifyMessage = 'Your safe alarm has been triggered...',
    blipSeconds = 30,              -- Map blip duration
    soundFile = 'sound1',          -- .ogg file in web/sounds/
    visualEffect = {
        enabled = true,
        duration = 9000,           -- UI alert duration (ms)
        title = 'SAFE UNDER ATTACK',
        subtitle = 'Break-in attempt detected',
        pulseCount = 3,
    }
}

Sound Toggle

Players can disable alarm sounds via the Settings tab in the NUI menu. This preference is stored in browser localStorage and persists across sessions.

Break-In System

Safes can be broken into using the Code Cracker item. The system supports configurable difficulty and security measures.

Break-In Flow

  1. Player uses Code Cracker on a placed safe
  2. System checks: owner online requirement, cooldown, lockout status
  3. Progress bar displays crack duration
  4. Success/failure determined by configured chance
  5. If alarm owned: owner notified, police dispatched, blip created
  6. If successful: temporary withdraw access granted
  7. If failed: lockout timer starts

Configuration

config.lua
Config.Cracking = {
    cooldownSeconds = 300,        -- 5 minutes between attempts
    crackDuration = 180000,       -- 3 minutes to crack
    successChance = 50,           -- 50% success rate
    failedLockoutSeconds = 180,   -- 3 minute lockout on failure
    allowedGroups = {},           -- Empty = anyone can attempt
    anyoneCanAttempt = true,
    grantsTemporaryWithdrawAccess = true,
    createRaidSession = false,
}

Owner Online Requirement

When this upgrade is owned, break-ins are blocked if the safe owner is offline. The burglar receives a notification: "The safe owner is not online. Break-in not possible."

Unknown Actor Masking

When a safe is accessed via code cracker, all transactions are logged with actor name as "Unknown". This maintains anonymity for the burglar.

Dynamic Weight System

Safe items dynamically increase in weight based on purchased upgrades, making upgraded safes heavier to carry.

How It Works

  • Base Weight: 15kg (configurable)
  • Weight Per Upgrade: 5kg added for each upgrade owned
  • Maximum Cap: 50kg - weight cannot exceed this limit

Upgrades That Add Weight

  • Storage Tier (each tier above 1 adds weight)
  • Alarm Upgrade
  • Owner Online Requirement
  • Tracking Upgrade
  • Access Control Upgrade

Example Calculation

A safe with Tier 3 storage + Alarm + Tracking:

Base: 15kg
+ Tier 3 (2 tiers above 1): +10kg
+ Alarm: +5kg
+ Tracking: +5kg
= 35kg total

Configuration

config.lua
Config.Safes = {
    -- ...
    baseWeight = 15000,           -- 15kg base (must match ox_inventory item weight)
    weightPerUpgrade = 5000,      -- 5kg per upgrade
    maxItemWeight = 50000,        -- 50kg maximum
}
Important: The baseWeight in config.lua should match the weight defined in your ox_inventory items.lua to prevent stacking issues.

Commands

Command Description Permission

Executes from server TX console only. Wipes all safe-related tables.
